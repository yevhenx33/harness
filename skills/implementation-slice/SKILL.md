# Implementation Slice

Recover the concrete task contract, authority, unfinished requirements, and
outcome-first design before editing. For a new feature, complete that design pass
first. For follow-up work, revisit invalidated assumptions rather than repeating
orientation. Inspect changed Git, configuration, owner, consumer, and check context.

Implement the sustainable owner-level solution under the root hygiene,
incremental-first, service-boundary, and authority rules. Prefer keyed reads and
mutations. Inspect helpers, serialization, hashing, persistence, and publication
for hidden full-dataset work. Preserve dependency propagation and equivalent results.

Use existing preflight checks for forbidden dependencies, invalid state, and wrong
artifacts. Put mechanical validation and commit decisions in deterministic code.
Bind evidence to its criterion, input/artifact, and environment. An exit code must
reflect the assertion; a successful process can still print a failed predicate.
For a new or uncertain gate, check a representative material failure too.

Make retries idempotent and bounded. Expired or cancelled work must not commit
later. Exercise material unavailable, malformed, stale, partial, duplicate,
ordering, cancellation, timeout, and retry states across the complete affected
path, including relevant unchanged stages. Verify progress, not only safe failure.

Prefer integration and invariant checks. Add unit tests only for otherwise
uncovered local behavior; preserve mandatory repository checks. Use the latency
skill for performance experiment methods when needed, not fixed sample quotas.

Apply both root completion passes before reporting done. Inspect the affected
render for visual changes and preserve exact requested copy/layout. For releases,
verify the active artifact identifies merged source and production does not depend
on the task worktree. Complete authorized delivery and post-merge cleanup.

At handoff, preserve the objective, granted authority, latest correction, owned
changes, verified criteria, unfinished checks, evidence, cumulative cost, and next
executable action in the existing task or change review. A handoff grants no new
cleanup, publication, rollback, or activation authority. Recheck changed facts on
resumption. Unavailable checks hold dependent acceptance, not independent work.
